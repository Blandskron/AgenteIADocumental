## 2. Clasificación estratégica de decisiones

1. **Funcionalidades existentes que NO necesitan cambios estructurales:** `ProfileServices`, `DocumentTransferServices`, `DocumentAccessServices` (asignaciones/borrado), núcleo JWT RS256 + `SecretsCipher`, arquitectura de roles SQL de privilegio mínimo, Design System *Floating Glass* y `CodeSandboxRunner` (solo endurecimiento menor).
2. **Funcionalidades existentes que deben fortalecerse:** `RagDocumentEmbeddingServices` (OCR español + PDFs escaneados + tablas + worker asíncrono), `RagDocumentChatServices` (citas con página/sección + SSE real + escape `</document_context>` + gate de evidencia), `AuthServices` (claims en registro, throttling cookie, rotación refresh), `DocumentSearchServices` (bug filtro `source`), `frontend/` (tablas Markdown, visor con página, `Ctrl+K`, auditoría paginada, onboarding).
3. **Funcionalidades parcialmente implementadas que deben completarse antes de abrir frentes nuevos:** `KnowledgeStudioServices` (reparar SQL `artifact_versions`, conectar LLM y worker, conectar `StudioPage.tsx` y `VerifiedVisualsPanel`) y `AgentOrchestratorServices` (corregir `AUTH_IDENTITY_URL`, `AuditLogger`, `PostgresRunsRepository`, handoff a Studio, prompt JSON fallback para Ollama y alinear `ADR_AGENT_ORCHESTRATOR.md`).
4. **Funcionalidades nuevas realmente necesarias:** Versionado documental (`document_versions`), etiquetas/metadatos editables, evaluación RAG real (HNSW + E5 + FTS + RRF), inteligencia documental proactiva persistida sobre documento completo, y script de backup automatizado.
5. **Capacidades que deben permanecer opcionales/experimentales (P2/P3):** Reranker local ONNX, `Docling` para layout complejo, reconocimiento/síntesis de voz (Whisper/Piper), webhooks salientes y sincronización incremental de Drive.
6. **Ideas descartadas explícitamente:** Base vectorial separada, broker Redis/RabbitMQ, librerías AGPL-3.0 en núcleo MIT, sandbox cloud, búsqueda federada SaaS y restricciones comerciales de licenciamiento.
