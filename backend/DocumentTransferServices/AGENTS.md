# DocumentTransferServices

Lee el [contrato y diagnóstico](README.md) y retoma la tarjeta del [tablero](../../ROADMAP.md#documenttransferservices). TRANSFER-001 documenta la base; las correcciones deben aportar evidencia antes de cambiar contratos.

- El servicio registra historial; no transfiere archivos ni acredita que el navegador los recibió. No conviertas un evento en permiso documental ni en auditoría autoritativa.
- Exige user_id entero positivo y exp entero vigente en JWT access. Separa propiedad del evento y acceso a la referencia documental según la política de Library/Access. Conserva historial privado incluso para administradores y tras revocación; enviar una referencia nueva o repetida requiere acceso vigente. Trata referencias ajenas como inexistentes.
- Conserva el mapeo metadata HTTP a metadata_ ORM y prueba round trip JSONB. En PATCH, ausente conserva, document_id/size_bytes null retiran, metadata {} vacía; otros nulos y PATCH vacío se rechazan. Respeta límites de esquemas y cuerpo de 64 KiB y no reflejes valores en errores. No impongas estas restricciones a datos históricos mediante borrados silenciosos.
- Al introducir el rol mínimo, conserva el bloqueo de referencia con capacidad acotada y prueba ambos órdenes frente al borrado. La FK de `transfer_events.document_id` existe en el esquema compartido y usa SET NULL. No deduzcas su ausencia del comentario del modelo ORM ni uses create_all como migración.
- Orden de escrituras: advisory por dueño, documento si se adjunta y luego evento con FOR UPDATE. Captura la respuesta antes de commit para no refrescar una fila ya limpiada; no devuelvas éxito si commit falla. Limpia por lotes SQL de hasta 1000, con contador efectivo, y conserva activos. Mantén documentos y archivos al borrar historial. Ejecuta scripts/database/transfer/audit_owners.sql en modo de solo lectura antes de reparar propietarios históricos. Ni siquiera un owner numérico prueba el origen de un antiguo sub/username: no reasignes ni borres automáticamente.
- Conserva las transiciones y la monotonía del dominio: no reabras terminales y exige 100 para COMPLETED. Reintentos PATCH idénticos no escriben otra vez. DocumentSearchPage/useDocumentQuestionFlow omiten progreso y referencia al fallar; las etapas no son bytes medidos.
- Mantén document-transfer-flows y tracked-transfer como recorrido compartido para Search/Chat/descarga. La cola del diario no espera ni repite el archivo y conserva su error original. Las advertencias aparecen fuera del modal; preservar activos si falla la recarga tras limpiar.
- GET transfers es página explícita con orden created_at/ID, limit hasta 200 y offset hasta 10000. Despliega adaptador/controlador/hook/modal y ambos consumidores juntos; no conviertas contratos incompatibles en listas vacías. Conserva generaciones por cliente y prueba respuestas tardías tras refresh, disposal y reinicio.
- Usa claves, documentos y registros sintéticos. Registra rollback o limpieza por IDs explícitos; las pruebas concurrentes requieren sesiones independientes.
- Desde la raíz ejecuta `docker compose -f docker/docker-compose.yml run --build --rm --no-deps transfer-tests` y la misma etapa con `ruff check --no-cache app tests`, tras arrancar el servicio según README. Las pruebas requieren TRANSFER_TEST_DATABASE_URL explícita, usan tablas temporales o rollback y claves sintéticas. No cargues .env automáticamente ni inyectes el entorno global en Compose. Al cierre retira scaffolding sin consumidores y deja README operativo, sin duplicar planes de modernización.
